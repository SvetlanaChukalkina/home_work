# Виджет банковских операций (в разработке) 
Цель проекта: создание виджета, показывающего несколько последних успешных банковских операций клиента. 
Виджет состоит из модулей masks, widget, processing, generators, decorators. В каждом модуле реализованы функции для работы с данными клиента.

## Модуль masks содержит функции get_mask_card_number и get_mask_account

### get_mask_card_number 
Функция get_mask_card_number маскирует номер банковской карты: принимает на вход номер карты и возвращает ее маску. 
Номер карты замаскирован и отображается в формате XXXX XX** **** XXXX, т.е. видны первые 6 и последние 4 цифры, остальные отображаются звездочками, номер разбит на блоки по 4 цифры, разделенные пробелами. 
#### Пример работы функции: 
входной аргумент - "7000792289606361", выход функции - "7000 79** **** 6361"

### get_mask_account 
Функция get_mask_account маскирует номер банковского счета: принимает на вход номер счета и возвращает его маску. 
Номер счета замаскирован и отображается в формате **XXXX, т.е. видны последние 4 цифры номера, а перед ними — две звездочки. 
#### Пример работы функции: 
входной аргумент - "73654108430135874305", выход функции - "**4305"

## Модуль widget содержит функции mask_account_card и get_date

### mask_account_card
Функция mask_account_card принимает строку, содержащую тип и номер карты или счета и возвращает строку с замаскированным номером. 
#### Пример работы функции для карты: 
входной аргумент - "Visa Platinum 7000792289606361", выход функции - "Visa Platinum 7000 79** **** 6361"
#### Пример работы функции для счета: 
входной аргумент - "Счет 73654108430135874305", выход функции - "Счет **4305"

### get_date
Функция get_date принимает на вход строку с датой в формате "2024-03-11T02:26:18.671407" и возвращает строку с датой в формате "ДД.ММ.ГГГГ".
#### Пример работы функции: 
входной аргумент - "2024-03-11T02:26:18.671407", выход функции - "11.03.2024"

## Модуль processing содержит функции filter_by_state и sort_by_date

{'id': 615064591, 'state': 'CANCELED', 'date': '2018-10-14T08:21:33.419441'}]

(статус по умолчанию "EXECUTED") - [{'id': 41428829, 'state': 'EXECUTED', 'date': '2019-07-03T18:35:29.512364'},

### sort_by_date

## Модуль generators содержит функции filter_by_currency, transaction_descriptions и card_number_generator

### filter_by_currency
Функция filter_by_currency принимает на вход список словарей, представляющих транзакции, и возвращает итератор, который поочередно выдает транзакции, где валюта операции соответствует заданной (например, USD).
#### Пример работы функции: 
usd_transactions = filter_by_currency(transactions, "USD")
for _ in range(2):
    print(next(usd_transactions))

### transaction_descriptions
Функция transaction_descriptions принимает список словарей с транзакциями и возвращает описание каждой операции по очереди.
#### Пример работы функции:

    print(next(descriptions))

### card_number_generator
Генератор card_number_generator выдает номера банковских карт в формате XXXX XXXX XXXX XXXX, где X — цифра номера карты. 
Может сгенерировать номера карт в заданном диапазоне от 0000 0000 0000 0001 до 9999 9999 9999 9999, принимая начальное и конечное значения для генерации диапазона номеров.
#### Пример работы функции:
##### for card_number in card_number_generator(1, 5):
#####    print(card_number)
#### Выход функции:
##### 0000 0000 0000 0001
##### 0000 0000 0000 0002
##### 0000 0000 0000 0003
##### 0000 0000 0000 0004

## Модуль decorators содержит декораторы, в том числе декоратор log

### log
Декоратор log автоматически логирует начало и конец выполнения функции, а также ее результаты или возникшие ошибки.
Он принимает необязательный аргумент filename, который определяет, куда будут записываться логи (в файл или в консоль).
Если filename задан, логи записываются в указанный файл, если нет - выводятся в консоль.
Логирование включает имя функции и результат выполнения при успешной операции либо имя функции, тип ошибки и входные параметры, если выполнение функции привело к ошибке.
#### Пример использования декоратора log:
##### @log(filename="mylog.txt")
##### def my_function(x, y):
######    return x + y
##### my_function(1, 2)
#### Ожидаемый вывод в лог-файл mylog.txt:
при успешном выполнении: "my_function ok";
при ошибке: "my_function error: тип ошибки. Inputs: (1, 2), {}", где тип ошибки заменяется на текст ошибки.

## Тестирование модулей

### Тестирование модуля masks

#### Тестирование функции get_mask_card_number: 
реализованы тесты правильности маскирования номера карты и работы функции на различных входных форматах номеров карт, проверка корректной обработки входных строк, 
где отсутствует номер карты.

#### Тестирование функции get_mask_account:
тесты для проверки правильности маскирования номера счета и для проверки работы функции с различными форматами номеров счетов. 
Функция корректно обрабатывает входные данные, где номер счета меньше ожидаемой длины.

### Тестирование модуля widget

#### Тестирование функции mask_account_card: 
реализованы тесты для проверки, что функция корректно распознает и применяет нужный тип маскировки, а также обрабатывает некорректные входные данные. Проведены 
параметризованные тесты с разными типами карт.

#### Тестирование функции get_date: 
проверка правильности преобразования даты и работы функции на различных входных форматах даты. Функция корректно обрабатывает входные строки, где отсутствует дата.

### Тестирование модуля processing

#### Тестирование функции filter_by_state: 
протестирована фильтрация списка словарей по заданному статусу state, проведена проверка работы функции при отсутствии словарей с указанным статусом state в списке.
Применена параметризация тестов для различных возможных значений статуса state.

#### Тестирование функции sort_by_date: 
реализовано тестирование сортировки списка словарей по датам в порядке убывания и возрастания, а также работы функции с некорректными форматами дат.
При одинаковых датах функция работает корректно.

### Тестирование модуля generators

#### Тестирование функции filter_by_currency: 
реализованы тесты, проверяющие, что функция корректно фильтрует транзакции по заданной валюте. Функция правильно обрабатывает случаи, когда транзакции в заданной валюте отсутствуют.
Генератор не завершается ошибкой при обработке пустого списка/списка без соответствующих валютных операций.

#### Тестирование функции transaction_descriptions: 
функция возвращает корректные описания для каждой транзакции, работает с различным количеством входных транзакций, включая пустой список.

#### Тестирование функции card_number_generator: 
согласно проведенным тестам, генератор выдает правильные номера карт в заданном диапазоне. Форматирование номеров карт осуществляется корректно. Генератор корректно обрабатывает крайние значения 
диапазона и правильно завершает генерацию.

### Тестирование модуля decorators:
для тестирования вывода в консоль применена фикстура capsys, которая позволяет перехватывать вывод данных в консоль.
Реализованы тесты, покрывающие различные сценарии использования декоратора, включая успешное выполнение функции и обработку исключения.
